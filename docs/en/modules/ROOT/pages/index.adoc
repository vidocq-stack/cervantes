= Cervantes
:description: MicroProfile JWT 2.1 implementation — signed-bearer-token RBAC for the Vidocq ecosystem — zero implementation dependency, strict Java Modules, virtual threads, Java 25.

[.text-center]
image::cervantes-logo.png[Cervantes,300,role=module-logo]

[.lead]
Cervantes is the MicroProfile JWT 2.1 implementation of the Vidocq ecosystem. It validates signed (and optionally encrypted) JWT bearer tokens using `java.security` exclusively, parses JSON through xref:champollion::index.adoc[Champollion], reads its configuration through xref:ravel::index.adoc[Ravel], exposes the `JsonWebToken` principal in CDI through xref:vauban::index.adoc[Vauban], and enforces `@RolesAllowed` on JAX-RS endpoints through xref:cassini::index.adoc[Cassini]. Goal: 100 % conformance to the MicroProfile JWT 2.1 TCK (achieved, *206 / 206* at M6), zero third-party crypto or JWT library, strict Java Modules, jlink-ready.

== Origin of the name

**Miguel de Cervantes (1547-1616)**, Spanish writer. Author of _The Ingenious Hidalgo Don Quixote of La Mancha_ (1605 / 1615), the first great work of modern literature. See https://en.wikipedia.org/wiki/Miguel_de_Cervantes[the Wikipedia article].

Don Quixote is not knighted: he _proclaims himself_ a knight-errant and carries with him the proofs of his rank — arms painted on his shield, copied letters patent, a heraldic narrative recited at every encounter. The picaresque story runs on that very mechanism: every interlocutor receives the claim, examines it, holds it as true or as folly. Cervantes invented the fiction of the _bearer of a signed identity_ — a character travelling with his own credentials and demanding that the world verify them.

A JWT is exactly that: a bearer token that presents a signed identity on every HTTP request, and that each service verifies locally, without contacting a central authority. Cervantes the runtime, unlike the windmills of La Mancha, does not take the bearer's claims at face value: it actually verifies the signature, issuer, audience and expiration, and grants a role only after the check.

| Knighthood disputed by the curate and the barber
| 401 if the signature lies, 403 if the role is missing
|===

== Three identifying traits

. **Zero third-party crypto or JWT library.** No Nimbus, no jose4j, no Bouncy Castle, no Auth0 java-jwt, no SmallRye JWT. All signature verification (RS256/384/512, ES256/384/512, JOSE R‖S ⇄ DER transcoding for ECDSA) runs through `java.security.Signature`. JWE decryption (`RSA-OAEP`, `A256GCM`) runs through `javax.crypto`. JSON parsing runs through xref:champollion::index.adoc[Champollion] (JSON-P 2.1).
. **Native `@RolesAllowed` without patching Cassini.** The JAX-RS integration sets a `SecurityContext` backed by the validated `JsonWebToken` and enforces `@RolesAllowed` / `@PermitAll` / `@DenyAll` through a `DynamicFeature`. Method precedence over class. 401 on invalid signature, 403 on missing role — entirely through the standard JAX-RS API, no implementation patch.
. **Strict Java Modules, virtual-thread-friendly, AOT-friendly.** Every artefact has its own `module-info.java`. `io.vidocq.cervantes.internal` is exported only to `io.vidocq.cervantes.cdi.vauban` (qualified export) — never to applications. No `setAccessible(true)` in production, no dynamic `Proxy`. JWKS fetching uses `java.net.http.HttpClient`, with no `synchronized` around I/O. Compatible with GraalVM native-image and Leyden CDS.

Cervantes consumes the ecosystem from the bottom up: xref:chappe::index.adoc[Chappe] serves the requests, xref:cassini::index.adoc[Cassini] hosts the auth filter and the `@RolesAllowed` `DynamicFeature`, xref:vauban::index.adoc[Vauban] triggers the BCE that synthesises the `@Claim` beans, xref:ravel::index.adoc[Ravel] resolves the `mp.jwt.*` keys, xref:champollion::index.adoc[Champollion] parses the JSON payload of the token. Cervantes adds the signed-identity layer — without rewriting anything else.
